# 编译说明 · 自己重打机器人 App

本目录是机器人 App（`com.ledi.agent`）的**完整可编译源码**。它**不用 Gradle**，
用 Android SDK 的 build-tools 直接走 `aapt2 → javac → d8 → zipalign → apksigner`
一条直线，好处是**编译链极短、离线可跑、易审计**。

---

## 1. 目录

```
07_源码/
├── agent/
│   ├── src/com/ledi/agent/…      自研 Java 源码（AI 大脑 + 全部控制接口，MIT）
│   ├── src/com/sinovoice/…       厂商 SDK 的接口层（按接口重写的调用面）
│   ├── assets/                   内嵌网页控制台(console.html)、表情/情绪词表、唤醒词表等
│   ├── libs/armeabi/*.so         厂商 native 库（离线唤醒/ASR/TTS/串口；见 NOTICE.md）
│   └── AndroidManifest.xml
├── ui_kit/appicon/               App 图标资源（aapt2 的 --res 输入）
├── tools/keys/                   （发布版**为空**——签名密钥不随仓分发，见 §2.1）
├── build_apk.py                  无 Gradle 的 APK 打包器（可移植版）
└── _rebuild_agent.py             一条命令重打（版本号自动改写 + 产物回读校验）
```

## 2. 需要什么

| 依赖 | 说明 |
|---|---|
| **Android SDK build-tools** | 需含 `aapt2`、`d8`、`zipalign`、`apksigner` |
| **android.jar** | `platforms/android-*/android.jar`（本项目在 android-36.1 上编译、产物 targetSdk 仍是 25，与机器人一致） |
| **JDK 17+** | `javac` 与 `d8` 都要用（源码按 `-source/-target 8` 编译） |
| **原厂包** | `05_原厂APK/xldrbt_v1.5.10.apk`（App 要**合并**它的 dex 并取部分 `.so`，缺了会崩进程） |

**路径配置（任选其一，能自动找到就不用设）**

| 环境变量 | 指向 |
|---|---|
| `ANDROID_BUILD_TOOLS` | build-tools 目录（最直接） |
| `ANDROID_SDK_ROOT` 或 `ANDROID_HOME` | Android SDK 根（会自动取最新 build-tools 与最新 platform） |
| `ANDROID_JAR` | 直接指定 `android.jar` |
| `JAVA_HOME` | JDK 根目录 |
| `LEDI_OEM_APK` | 自定义原厂包路径（默认 `../05_原厂APK/xldrbt_v1.5.10.apk`） |

> `build_apk.py` 找不到工具链会**直接报错退出**，不会静默产出一个坏 APK。

## 3. 一条命令重打

```bash
cd 07_源码
python _rebuild_agent.py v300
# -> dist/LediAgent.v300.apk
```

它做三件事（都写进脚本、不靠人记）：
1. **版本号唯一事实源**：把 `v300` 写进 manifest 的 `versionCode=300 / versionName=1.0-v300`；
2. 调 `build_apk.py` 打包（合并原厂 dex、打入 `.so`、编译资源、签名）；
3. **回读产物**用 `aapt2 dump badging` 核版本号 —— 产物里对不上就报错（防"字节数对得上、里面的东西没进去"）。

想先看命令不执行：`python _rebuild_agent.py v300 --dry`。

## 4. 关键点（踩过的坑，别再踩）

- **必须合并原厂 dex**：App 复用原厂引擎（串口 / 唤醒 / TTS），
  这些类在 `xldrbt_v1.5.10.apk` 的 `classes*.dex` 里，靠 `--merge-dex` 并进本包。
- **`.so` 用"减法"取**：`原厂有的 − 本地已有的`，逐个补搬。写死名单会踩两个相反的坑
  （搬重复 → 签名失败；漏搬 → ASR 解码器一用就 `UnsatisfiedLinkError` 崩进程）。
- **必须用平台签名**：这颗 ROM 的 PMS 有签名闸门，**只收平台签名的包**。
  签名密钥**不随本仓分发**（私钥 = 闸门本身，见 `NOTICE.md` §4）——自备方式见 §2.1。

### 2.1 关于签名密钥（发布版缺这个，别跳过）

`build_apk.py` 在签名一步会找 `platform.p12`，查找顺序：**环境变量 `LEDI_SIGN_KEYS` → `tools/keys/`**，
找不到会**明确报错退出**（不会产出坏 APK）。

自备步骤：
1. 取 **AOSP platform 测试密钥**（`build/target/product/security` 的 `platform.pk8` + `platform.x509.pem`，
   口令 `android`）——或你手上设备对应的平台密钥；
2. 转成 PKCS#12（`openssl pkcs12 -export -in platform.x509.pem -inkey platform.pk8 -out platform.p12 -name platform -passout pass:android`）；
3. 放到仓库外任意目录，`set LEDI_SIGN_KEYS=<那个目录>`。

> 只想装 App 不想编译的：直接用随包的 `03_App/LediAgent.public-v223.apk`（已用该密钥签好），完全不需要密钥。
- **资源不能漏**：不给 `--res` 会产出**没有图标**的 APK。脚本已固化 `--res ui_kit/appicon`，
  并在打包中**断言** `res/mipmap/*` 真的进了包。

## 6. 更细的用法

`build_apk.py` 是通用打包器，也可单独用：
```bash
python build_apk.py --name MyApp --src agent/src --manifest agent/AndroidManifest.xml \
  --out dist/MyApp.apk --merge-dex ../05_原厂APK/xldrbt_v1.5.10.apk \
  --libs-from ../05_原厂APK/xldrbt_v1.5.10.apk --libs-dir agent/libs \
  --assets agent/assets --res ui_kit/appicon --sign platform
```
`python build_apk.py -h` 看全部参数。
